Decisión EC-8 (semántica de `count: null` sin `error`): se trata como **error** (todo-o-nada, `counts=null` + mensaje neutro), NUNCA como 0. Razón: PostgREST puede devolver `count: null` en una respuesta de `head:true` cuando algo salió mal en el conteo (p.ej. RLS deniega silenciosamente o el header `Prefer: count=exact` no se aplicó); fabricar un 0 en ese caso le miente al admin diciéndole "cola vacía" cuando en realidad no se pudo leer. Un error visible es preferible a un dato falso — mismo criterio que EC-1/EC-11/EC-24 de `useAdStats` (`totals=null` nunca ceros fabricados) y que el docblock de `usePendingAds` (fallar cerrado).
